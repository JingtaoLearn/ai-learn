# Information sources

The Owner chooses sources that can change its product decision. Existing Agent
and product systems provide runtime evidence; the framework repository is not
an ingestion service or execution database.

## Consult as needed

- Product-group messages and report Threads.
- Current Owner and bounded specialist conversations.
- Native Kanban tasks, results and review evidence.
- Product code, Git history, Issues, PRs and owning-system state.
- Product artifacts, experiments, reports, health and logs relevant to the Goal.
- Official web documentation and knowledge resources for unresolved facts.

Product-local Goal, Principles and compact recovery context remain ordinary
Agent context. This framework checkout supplies reusable definitions/templates;
it does not receive live copies of those instances. A busy source is not
necessarily important, and a running service proves liveness, not usefulness.

Use native message_agent for appropriate conversation, Kanban for durable work,
and supported Heartbeat/event mechanisms for continuity. Check installed-release
behavior before depending on a route; failed wake/Thread semantics are not an
excuse to restore a custom callback adapter.
